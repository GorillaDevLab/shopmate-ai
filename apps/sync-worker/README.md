# Durable demo sync worker

This package provides a verified common-target coordinator, restricted commerce read composition, strict persisted-work projection, bounded durable page runners, a fresh grant-scoped fault loader, and a demo-only CLI. PostgreSQL/profile/scenario acceptance is required before declaring the complete P2 capability accepted.

`SyncCommerce` opens the existing read-only connector from a freshly checked server runtime bootstrap and restricted source ports. Factory access rechecks current authority and refreshes the persisted business clock. `CheckpointReadPort` can recover expired signed continuations without changing their original cutoff or committing business cursor progress. All five read streams are supported. `SyncPageRunner` commits business facts and cursors through the existing atomic sync-host SDK; startup composition must supply the checked connector and runtime opening.

`planSyncWindows(input)` accepts a closed normalized projection and validates it at runtime, including bounded identifiers, exact canonical UTC milliseconds, five unique stream slots and data-only objects. Accessors, proxies, custom prototypes and unknown fields are rejected without invoking user getters or proxy traps.

The caller must first validate the server-derived runtime bootstrap with the database SDK and verify the immutable source publication with the restricted source reader. Project those validated results into `WindowPlannerInput`:

- `binding`: the worker's fixed `grantId`, `provider: "MOCK"`, complete source `scope`, and grant `initialSince`.
- `bootstrap`: only the current `scope`, actual UTC `businessNow`, and `READY` or `WAITING_RUNTIME` state. The SDK owns READY/runtime opening consistency. The planner does not require `initialSince` to equal runtime opening.
- `publication`: `null` when unpublished; otherwise verified `scope`, `targetTime`, and `processedThrough`. A published source with zero events still has valid coverage; event counts are irrelevant to planning. This structural projection does not itself authenticate a certificate.
- `latestJobs`: at most one latest job per stream, each containing only `grantId`, `provider`, `scope`, `stream`, canonical `since`/`until`, and `status`. Parse raw `list_work` JSON before projection. SQL job identity lacks sessionId; attach the fixed session scope only after checking the job's full persisted binding against the validated bootstrap. Never pass raw SQL job JSON directly.

Scope consists of organization, workspace, store, session, connection, external store and generation. Each projection must match the fixed binding. Historical contiguity and terminal receipt proof remain enforced by `create_window` and database triggers; the planner cannot certify history omitted from a latest-job projection. `SUCCEEDED.until` is durable consecutive receipt progress even when business freshness is unknown. The planner intentionally does not consume `successfulThrough` or assert sync freshness.

Fresh windows share the minimum of the actual business clock, verified publication target/coverage and every stream's start plus 31 elapsed UTC days. Each start is the latest completed job's `until`, or grant `initialSince` for a missing stream. Streams already at that common target are skipped.

Any unfinished latest job freezes its original target, including READY, RUNNING and FAILED jobs. Existing jobs appear in `existingStreams`; only missing/lagging streams appear in `windows`. Conflicting unfinished targets, completed progress beyond the frozen target, or a missing stream that cannot reach that target in one contiguous 31-day window are rejected. Insufficient current clock or publication coverage waits without creating windows.

A `PLANNED` result contains the target, whether it is frozen, windows to create, and existing streams to resume. A `WAITING` result always has an empty `windows` array and one of `WAITING_RUNTIME`, `WAITING_PUBLICATION`, `WAITING_COVERAGE`, or `CAUGHT_UP`. Callers remain responsible for rechecking server authority when applying advisory plans.

`projectSyncWork(raw, checkedBootstrap)` checks the exact SQL grant/job field sets and full persisted binding, principal, provider, generation, and initial opening. It normalizes SQL timestamps, rejects hostile descriptors and duplicate/extra stream slots, and supplies immutable jobs and planner projections. SQL remains responsible for receipt history and status legality.

`new SyncPageRunner(pinnedHost, selectedConnector, checkedRuntimeOpening).run(job, controls)` runs one checked job. Controls support `maxPages` (default 100, range 1–1000), `budgetMs` (default 60000, range 1–3600000), and an optional caller `AbortSignal`. Results contain actual durable `job` progress and one reason: `SUCCEEDED`, `PAGE_LIMIT`, `BUDGET`, or `STOPPED`. A fresh runner claims even RUNNING jobs; same-instance ownership is explicitly retained with its two-minute lifetime. Foreign active leases propagate their SDK error and never become connector failures.

Each page renews before and after fetching, shares an absolute deadline of at most 25 seconds across at most three attempts, and commits using the original persisted cursor and `page-${pageCount + 1}`. Products, orders, refunds, and inventory omit incremental `since`; marketing reads from the checked runtime opening. Only actual TEMPORARY/TIMEOUT/RATE_LIMIT result failures retry, with signal-aware delays bounded by remaining page time. Exhausted retryable failures mark the job failed; stop/budget results do not. Unknown thrown errors and uncertain commit acknowledgements propagate without refetching. SDK results are checked for stable identity and expected lease/progress transitions, and freshness is normalized.

`SyncCoordinator(pinnedHost, sourceReader).pass(controls)` verifies physical publication through the restricted reader and rechecks runtime authority after publication/work reads and immediately before each window creation. It pins grant, principal, merchant, provider, full scope, initial opening, configuration/hash, generator and runtime opening. Current clock/session revisions may advance; the latest business clock bounds every creation. Partial creation leaves durable windows that freeze the next pass target. Each latest unfinished job retains its own runner on the same backend, while the selected connector is refreshed each pass. Drift/revocation and foreign active leases propagate errors.

The pass shares one absolute budget across discovery, planning, creation and all runners. Controls use the same bounds as the page runner. Results are `WAITING`, `PROGRESSED`, `BUDGET` or `STOPPED`, with actual `created` jobs and actual page `outcomes`; waiting results include the planner reason. Window/commit RPCs are awaited even when a signal arrives so their actual receipts can be preserved. A thrown uncertain acknowledgement remains an error and is never reported as a successful mutation.

`createSyncFailureRuleLoader(host, checkedBootstrap)` validates its actor/full scope and reads fresh SDK-validated immutable rules between bootstrap authority checks. Read controls reject accessors/proxies and nonnative signals, retain the original absolute deadline and cap each read at 25 seconds. Immutable drift or unavailable authority denies access; clock/session revisions may advance. The coordinator wires this loader into each freshly composed MOCK connector; business page runners select streams through the generic connector contract.

Build first with `pnpm --filter @shopmate/sync-worker build`, then run `pnpm --filter @shopmate/sync-worker start --once` for one pass, or `pnpm --filter @shopmate/sync-worker start` for daemon polling every five seconds. Only `--once` or no arguments are supported. Required environment variables:

- `APP_ENV=demo` and `ENABLE_DEMO_MODE=true`.
- `SYNC_WORKER_GRANT_ID`: a bounded SDK grant identifier; the principal and all bindings come from the server.
- `SYNC_WORKER_DATABASE_URL`: a dedicated restricted sync-host login.
- `MOCK_PLATFORM_READ_DATABASE_URL`: a separate restricted source reader login; no application database fallback.
- `MOCK_SOURCE_CURSOR_KEY`: the existing source cursor secret, 32–4096 UTF-8 bytes.

No caller identities or target timestamps are accepted. The SDK verifies database-role restrictions on actual connections. The CLI validates configuration before opening resources, closes both connections on startup failure and every exit, removes signal handlers, and uses abort-aware polling for SIGINT/SIGTERM. Normally returned WAITING, PROGRESSED and BUDGET passes continue polling; thrown permission, generation, malformed-response and storage failures terminate without automatic retries. Output contains only status/reason and actual job/outcome counts; errors emit `SYNC_WORKER_FAILED` without raw SDK errors or credentials. Importing the package does not start the CLI.
