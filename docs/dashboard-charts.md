# 经营图表与自动选图

## 查询与展示分开

图表生成使用一次受限查询规划请求。模型输出经过字段、指标、分组、聚合和日期范围校验的 DSL，不执行模型生成的 SQL。后端继续使用带权限检查和商家范围的业务读取服务。

请求 `kind` 支持 `auto`、`pie`、`bar`、`line`、`area`、`report`。`auto` 仅用于生成请求，保存的查询必须有确定的 `visualization`。

| 查询形态                   | 自动呈现 | 可复用同一结果的视图       |
| -------------------------- | -------- | -------------------------- |
| 按日期的销售额             | 折线     | 折线、面积、柱状           |
| 商品、门店或渠道等分类对比 | 条形     | 条形；可加总指标可使用环形 |
| 明确询问构成、份额或占比   | 环形     | 环形、条形                 |
| 平均客单价等平均指标       | 条形     | 条形，不计算总和或占比     |
| 不分组的经营摘要           | 报告     | 报告                       |

指标与分组仍受现有业务注册表限制，并非任意指标都支持所有维度。商品计数暂不支持分类图，需取消分组后生成报告；不兼容请求返回 `INSIGHT_VIEW_INCOMPATIBLE` 和明确中文说明，`allowedViews` 可以为空。

## 数据口径

- 分类结果沿用 `kind: pie` 的历史数据形状，最多返回 12 项；它也可以由条形图展示。
- 时间序列使用 `kind: series`，包含按日期严格升序且不重复的 `{date, value}`，最多 366 点。不会套用分类排行的 Top N 截断。
- 图表层不把缺失观测补成零。业务服务确认某日没有销售时返回的零值，可以正常展示。
- 图中的合计、百分比与“其他”只基于本次返回结果，不代表被截断范围之外的全店总额。
- `currencyMinor` 的数值是人民币分，界面按元显示；`count` 与 `ratio` 保持自身单位。

## 保存兼容

布局仍为版本 3，历史 `pieChart` 组件键保留，显示名称为“AI 图表”。`config.view` 是可选的展示偏好，与查询本身分开；销售趋势卡也支持可选的折线/面积偏好。

旧版饼图与报告查询保留读取路径。尤其旧版按日期饼图可能只是分类 Top N 结果，不能把它冒充完整时间序列；需要重新生成日期趋势查询才能得到完整序列。旧分组报告的读取兼容不代表新报告规划允许相同分组。

## 不产生费用的验证

开发验证应使用 mock provider、Vitest 替身和浏览器拦截接口，不运行真实 DeepSeek 或生产数据库集成流程。核心检查包括：30 天序列不截断、非法视图明确报错、租户隔离不变、旧布局可读、切换呈现不重复生成或查询。

本功能没有新增数据表，也不导入线上演示数据。真实环境能展示多少内容，取决于相应商家、日期与门店范围内已有的业务记录。
