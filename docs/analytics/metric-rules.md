# ShopMate Analytics Metric Rules v0.1

本文件冻结 Demo v0.1 的库存风险与销售指标计算规则。

## 1. 输入范围

销售指标只使用 E1 返回的有效订单：

- 必须属于当前 Merchant
- CANCELLED 订单不参与销售指标
- 日期范围按照 Asia/Shanghai 自然日处理

## 2. 所选时段日均销量

默认最近 7 个自然日；看板可选择最近 30 天或 1–31 天自选区间。记所选区间的自然日天数为 N（含首尾）：

日均销量 = 所选时段有效销量 / N

- 即使某些日期没有销售，也仍然除以 N
- 展示值保留 2 位小数

## 3. 预计售罄天数

当所选时段销量大于 0：

预计售罄天数 = 当前库存 × N / 所选时段销量

库存使用当前快照，即使所选时段在历史上，也不表示该时段的历史库存。内部 `soldUnits7d` 为兼容既有调用保留的字段名，在显式区间下代表该区间销量；对外响应统一为 `recentSold`。

规则：

- 库存 = 0：返回 0 天
- 库存 > 0 且所选时段销量 = 0：返回 null
- 非 null 结果保留 1 位小数
- 正库存的最小展示值为 0.1 天，只有零库存返回 0 天
- 不允许零销量除零

## 4. 库存风险等级

按以下顺序判断：

1. OUT_OF_STOCK
   - 当前库存 = 0

2. CRITICAL
   - 预计售罄天数 <= 3

3. WARNING
   - 预计售罄天数 <= 7
   - 或当前库存 <= alertThreshold

4. NORMAL
   - 不满足以上条件

## 5. 销售指标

销售额：

- 有效订单 totalAmount 合计

订单数：

- 有效订单数量

销量：

- 有效订单所有 OrderItem.quantity 合计

客单价：

- 销售额 / 有效订单数
- 0 个订单时返回 0

## 6. 金额规则

所有金额计算统一转换为整数“分”。

例如：

79.00 CNY = 7900 cents

禁止使用浮点金额进行累计。

客单价最终使用整数分四舍五入，然后格式化为两位小数。

## 7. 趋势

看板变化比较所选周期和紧邻其前的等长周期；例如 8 月 2–31 日对比 7 月 3 日–8 月 1 日。每日趋势覆盖所选范围，无销售的日期补零，前端不重算金额或百分比。

current > previous：

- UP

current < previous：

- DOWN

current = previous：

- FLAT

previous = 0 且 current > 0：

- NEW
- changePercent = null

没有历史周期：

- NO_HISTORY
- changePercent = null

其他情况下：

changePercent =
(current - previous) / previous × 100

保留 1 位小数。

## 8. 热销规则

当前周期按以下顺序排序：

1. 销量降序
2. 销售额降序
3. productId 升序

前 3 名标记为 hot seller。

该规则保证并列结果稳定。

## 9. 低表现规则

满足任一条件：

- 当前销量 = 0
- 与上期相比销量下降至少 30%

则标记为 LOW。

其他商品标记为 NORMAL。

## 10. 可追溯性

所有 Analytics 计算函数必须：

- 接收明确输入
- 不依赖随机数
- 不依赖当前机器时间
- 使用纯计算规则
- 能通过 Fixture / 单元测试复算结果
