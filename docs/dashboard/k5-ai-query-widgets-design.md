# K5 AI 查询 DSL 与饼图报告组件设计

## 背景与目标

K5 将自然语言经营问题转换为受限、可验证的查询 DSL，并把结果呈现为可加入用户看板的饼图或报告卡片。系统不得执行模型生成的 SQL 或代码，所有查询必须经过服务端字段注册表、范围、聚合和身份边界校验。

Demo 阶段使用当前数据库中的销售、商品和库存数据。数据契约预留 `platform` 与 `storeId`，以便后续通过连接器接入淘宝、抖音电商、小红书等平台；K5 不包含真实平台 OAuth 和同步实现。

## 用户体验

### AI 聊天入口

1. 用户在经营助手中描述想要的分析，例如“生成近 30 天各商品销售额占比饼图”。
2. 服务端返回中文解释及一个结构化的看板组件建议。
3. 组件直接加入当前看板草稿，并显示可撤销反馈。
4. 用户可以撤销、在编辑页面删除或继续调整组件尺寸。
5. 只有点击“完成并保存”后，布局才持久化；离开或放弃修改不会覆盖已保存布局。

### 组件库入口

1. 用户选择“AI 饼图”或“AI 报告”。
2. 输入自然语言问题并生成预览。
3. 预览包含标题、查询摘要、数据或报告内容，以及加载、空结果和错误状态。
4. 用户确认后将组件加入草稿，也可取消而不修改布局。

## 架构

```text
自然语言问题
    ↓
LLM 生成候选 DSL
    ↓
Zod 严格解析 + 字段注册表校验
    ↓
服务端注入 AuthContext 与店铺范围
    ↓
受限查询执行器调用领域 Service/Repository
    ↓
结构化饼图或报告结果
    ↓
加入 Dashboard 草稿 → 用户显式保存
```

系统采用可扩展字段注册表，而不是把数据库表名和列名暴露给模型。新增业务字段时需要在注册表中声明其业务名称、类型、允许的聚合、允许的筛选和实际执行器映射。

## 受限查询 DSL

DSL 只描述业务意图，不包含 SQL、表名、列名或身份字段。第一版包含：

- 数据集：`sales`、`products`、`inventory`
- 指标：销售额、订单量、销量、客单价、可用库存、商品数量
- 维度：日期、商品、SKU、订单状态、库存风险；预留平台和店铺
- 聚合：`sum`、`count`、`average`
- 筛选：日期范围、状态、商品或 SKU 标识、平台和店铺标识
- 排序、结果上限与可视化类型

日期范围不设置 31 天上限，但必须满足开始日期不晚于结束日期。服务端通过最大分组数、最大返回项数、查询超时和受控粒度保护性能。

示例：

```json
{
  "dataset": "sales",
  "metric": "revenue",
  "groupBy": "product",
  "dateRange": { "start": "2026-08-01", "end": "2026-08-31" },
  "filters": [],
  "order": "desc",
  "limit": 8,
  "visualization": "pie"
}
```

## 字段注册表

每个注册项包含稳定 key、中文标签、数据类型、允许的角色和执行映射：

- `metric`：允许的聚合方式与数值单位。
- `dimension`：允许的分组和筛选操作。
- `filter`：允许的操作符、值类型和数量限制。
- `source`：由领域服务实现的查询路径，不向 LLM 暴露数据库细节。

`platform` 和 `storeId` 在 Demo 中可以为空或指向模拟店铺。真实平台接入后，连接器负责将平台字段映射为这些统一字段，AI 与组件无需修改。

## 查询执行与身份隔离

- Controller 必须经过现有认证守卫。
- `userId`、`merchantId` 来自 `AuthContext`，不得出现在客户端或 LLM 生成的 DSL 中。
- `storeId` 必须由服务端验证属于当前 Merchant；Demo 尚无店铺表时，只接受缺省店铺范围。
- 查询执行器使用参数化 Prisma 查询或调用现有 Analytics Service，禁止拼接 SQL。
- 注册表之外的字段、聚合、筛选和可视化类型一律拒绝。
- 返回统一的可重试错误结构，不向客户端泄露 Provider、数据库或内部堆栈信息。

## API 与数据契约

新增经过认证的预览端点，接收自然语言问题及目标组件类型，返回规范化 DSL、查询摘要和结构化预览结果。保存到布局中的卡片只包含经过服务端规范化的查询定义与展示配置。

聊天响应增加可选的组件建议字段；纯问答响应保持兼容。前端只消费经过共享 Zod Schema 校验的数据。

布局 Schema 增加 `pieChart` 和 `report` 两类卡片。由于这是持久化契约变化，布局版本升级，并提供旧版布局的兼容解析与迁移，避免已保存用户布局失效。

## 组件数据与刷新策略

- 布局持久化查询定义，而不是把一次查询结果当作永久数据保存。
- 看板加载时使用当前登录上下文重新执行已保存查询，确保数据更新且不跨用户复用。
- 相同页面中的查询可以在客户端去重；单卡失败不阻塞其他卡片。
- 饼图最多展示有限分组，并将其余数据合并为“其他”或按查询限制截断。
- 报告由标题、摘要、要点和可选指标组成，不允许服务端返回可执行 HTML。

## 安全渲染

- 报告内容以纯文本和结构化数组传输，React 默认转义渲染。
- 禁止 `dangerouslySetInnerHTML`、动态脚本、任意 URL 和模型生成样式。
- 标题、摘要和要点设置长度及数量上限。
- 卡片 ID 由客户端安全生成并继续接受现有布局 Schema 校验。

## 草稿、撤销与保存

AI 新增组件复用 K4 的草稿状态机：

- 直接插入时生成一个可逆的草稿操作。
- 撤销恢复插入前的卡片顺序和配置。
- 删除属于草稿编辑，保留现有破坏性操作确认规则。
- 预览模式展示草稿结果，但不触发保存。
- 保存继续使用现有 revision 乐观并发控制；失败时草稿和错误状态保留。

## 测试与验收

- Contracts：合法 DSL、未知字段、身份字段注入尝试、范围、聚合、数量与布局版本迁移。
- API：认证、Merchant 隔离、参数化查询、空数据、超时、Provider 失败和结构化错误。
- Agent：自然语言生成合法 DSL，非法候选不会进入执行器。
- Web：聊天直接添加、组件库预览、撤销、删除、显式保存、保存失败恢复及 375px 操作。
- 安全：确认不存在任意 SQL/代码执行、HTML 注入和客户端身份越权字段。
- 质量门禁：相关单元/集成测试、TypeScript、Lint、Build 与 Secret Scan 通过。

## 非目标

- 淘宝、抖音电商、小红书等真实平台授权与数据同步。
- 任意数据库 Schema 探索或自由 SQL。
- 自动保存 AI 生成组件。
- 复杂 BI 公式编辑器、跨 Merchant 分析和后台长任务调度。
