# K6 站内监听规则与提醒设计

## 目标与范围

K6 为当前商家的经营数据增加可配置监听能力。用户可以创建、预览、确认、停用和删除销售或库存监听规则，并在站内提醒中心查看命中结果与执行失败状态。

本阶段只读取 ShopMate 数据库中已经存在且属于当前 Merchant Scope 的数据。淘宝、抖音、小红书等平台连接器、真正的后台任务队列、邮件、短信和系统推送不在 K6 范围内。

## 产品流程

### 创建规则

1. 用户在监听管理界面用自然语言描述需要关注的问题。
2. AI 只能通过受限工具 Schema 生成规则 DSL，不得生成 SQL、代码或身份字段。
3. 服务端严格校验规则类型、指标、运算符、阈值、分析范围和频率，再使用当前认证上下文执行一次预览。
4. 页面展示规范化规则说明和当前命中结果。预览不会保存规则或创建提醒。
5. 用户点击“确认并启用”后才保存规则。

### 执行规则

- 规则支持每日和每周两种频率，最短每日执行一次。
- 规则分析范围只能是最近 7、30 或 90 天。
- 用户登录或打开看板时，Web 调用服务端同步端点；服务端只执行当前用户已到期的启用规则。
- 用户可以点击“立即检查”执行单条规则，不受 `nextRunAt` 限制，但仍受认证、资源上限和去重规则约束。
- 同步请求只做有限工作：单次最多执行 10 条规则，每条规则最多产生 20 个命中结果。
- 每次执行后更新 `lastRunAt` 和 `nextRunAt`。每日规则从本次执行时间向后推 24 小时，每周规则向后推 7 天。

这种“到期补算”能在 Demo 中表现周期监听，同时不要求部署常驻 Cron。用户离线期间不会即时收到提醒；下次登录或打开看板时会补算一次最新周期，不逐个回放遗漏周期。

### 管理与提醒

- 每个 `userId + merchantId` 最多保存 10 条启用规则。
- 用户可以停用或重新启用规则。停用后不再参与到期补算。
- 删除规则需要二次确认；删除规则同时级联删除该规则的站内提醒。
- 看板头部提供提醒入口和未读数量。
- 提醒中心按创建时间倒序展示提醒，可将单条或全部标记为已读。
- 规则执行失败不会自动停用或删除规则。页面展示最后失败原因和“重新检查”入口。

## 规则模型

规则 DSL 是严格判别联合，只允许以下两类：

### 销售规则

- 类型：`salesThreshold`
- 指标：`revenue`、`orderCount`、`unitsSold`、`averageOrderValue`
- 运算符：`above`、`below`
- 阈值：有限非负数；金额统一使用分作为服务端数值单位
- 范围：`7d`、`30d`、`90d`
- 频率：`daily`、`weekly`

销售规则以整个商家在统计范围内的汇总指标为命中对象。

### 库存规则

- 类型：`inventoryThreshold`
- 指标固定为 `inventory`
- 运算符：`below`
- 阈值：0 至 1,000,000 的整数
- 范围：`allProducts`
- 频率：`daily`、`weekly`
- 可选商品范围：最多 20 个商品 ID；为空表示全部商品

库存规则按 SKU 检查，命中提醒包含商品、SKU 和当前库存。

所有请求 Schema 使用 strict object。客户端和 AI 输出中的 `userId`、`merchantId`、任意数据库字段名或额外字段都会被拒绝。

## 数据模型

### `UserMonitoringRule`

- `id`
- `userId`
- `merchantId`
- `name`
- `kind`
- `definition`：已通过共享 Schema 校验的 JSON DSL
- `frequency`
- `status`：`ACTIVE` 或 `INACTIVE`
- `lastRunAt`
- `nextRunAt`
- `lastErrorCode`
- `lastErrorMessage`
- `createdAt`
- `updatedAt`

索引覆盖 `(userId, merchantId, status, nextRunAt)`。所有读取、更新和删除都同时使用 `userId` 与 `merchantId`，避免同商家不同用户互相看到私人规则。

### `MonitoringNotification`

- `id`
- `ruleId`
- `userId`
- `merchantId`
- `fingerprint`
- `title`
- `message`
- `severity`：`INFO`、`WARNING` 或 `CRITICAL`
- `resourceType`：`MERCHANT` 或 `SKU`
- `resourceId`
- `periodStart`
- `periodEnd`
- `readAt`
- `createdAt`

`(userId, merchantId, fingerprint)` 建立唯一约束。指纹由规则 ID、命中资源和规范化统计周期组成，不包含模型自由文本，因此同一规则、同一对象、同一周期重复执行不会重复提醒。

## 服务端架构

### 合约层

共享 contracts 定义：

- 规则 DSL、预览请求与响应
- 创建、列表、更新状态和删除接口
- 同步与立即执行响应
- 提醒列表、未读数量和标记已读接口
- 中文且结构化的错误响应

### 规则服务

规则服务负责严格校验、用户资源上限、预览、保存和状态变更。预览复用现有销售汇总、商品和库存领域服务，不直接访问 Prisma。

### 执行服务

执行服务接收认证上下文和已经校验的规则：

1. 通过领域服务读取当前 Merchant Scope 数据。
2. 计算规范化统计周期和命中结果。
3. 在事务中按指纹写入提醒并更新运行状态。
4. 唯一约束冲突视为已去重，不返回内部数据库错误。
5. 失败时记录安全、可展示的错误代码和中文信息，不保存 Secret、堆栈或第三方原始响应。

### API

所有端点位于 `/api/v1/monitoring` 且默认需要认证：

- `POST /rules/preview`
- `POST /rules`
- `GET /rules`
- `PATCH /rules/:id/status`
- `DELETE /rules/:id`
- `POST /rules/:id/run`
- `POST /sync`
- `GET /notifications`
- `GET /notifications/unread-count`
- `PATCH /notifications/:id/read`
- `POST /notifications/read-all`

路由参数、查询参数和请求体均在进入业务逻辑前校验。不存在或越权的资源统一返回 404，防止枚举其他用户规则和提醒。

## 前端设计

### 监听管理器

监听管理器从看板头部进入，移动端以全屏面板展示，桌面端使用宽侧边面板。包含：

- 自然语言输入和销售/库存示例问题
- 生成预览的加载、错误与重试状态
- 规范化条件、频率和当前命中结果预览
- “确认并启用”按钮
- 已保存规则列表及启用状态、下次检查、最后结果和失败信息
- “立即检查”、停用/启用和删除操作

删除按钮打开确认对话框。所有操作提供明确状态反馈，不能只依赖颜色表达结果。

### 提醒中心

看板头部铃铛显示未读数量。提醒面板包含加载、空、错误三态，按时间倒序列出标题、摘要、严重程度、来源规则和时间。单条提醒可标记已读，并提供“全部已读”。本阶段不提供外部跳转或自动修改库存。

## 安全与资源限制

- 身份只来自服务端 Session，客户端不提交 `userId` 或 `merchantId`。
- AI 只生成受限 DSL；服务端再次严格校验，不执行自由 SQL 或代码。
- 单用户、单商家最多 10 条启用规则。
- 频率不短于每日，统计范围只允许 7、30、90 天或库存全部商品快照。
- 单条库存规则最多指定 20 个商品，单次执行最多处理 20 个命中结果。
- 提醒标题和正文由服务端模板生成，不渲染 HTML。
- 删除规则需要二次确认。

## 错误处理

- 无效请求：400，返回稳定错误代码与中文说明。
- 未认证：401。
- 越权或不存在：404。
- 启用规则超过上限：409。
- 并发重复提醒：依靠唯一约束去重并视为成功。
- 数据读取或 AI Provider 失败：预览返回可重试错误；已保存规则记录失败状态并保留上次成功提醒。
- 前端请求失败时保留现有规则和提醒，不使用空数组覆盖已加载数据。

## 测试策略

- Contracts：严格 Schema、非法额外字段、范围与频率限制、响应格式。
- Database：迁移约束、用户与商家索引、提醒指纹唯一性和级联删除。
- API 单元测试：规则求值、下一次执行时间、去重、上限、失败状态和跨用户隔离。
- API 集成测试：未认证 401、伪造身份字段被拒绝、其他用户资源返回 404。
- Web 单元测试：预览后确认、规则状态操作、删除确认、提醒三态、已读操作和移动端语义。
- 完整质量门禁：格式、Lint、TypeScript、测试、构建和 Secret 扫描。

## 后续扩展

未来接入真正任务队列时，只需由调度器调用同一个到期执行服务；规则、去重和提醒模型无需改变。平台连接器完成后，可以在规则 DSL 中增加受注册表限制的 `platform` 和 `storeId` 范围，但 K6 不开放这些字段。
