# iOS 风格小组件布局与流动换位设计

## 目标

把经营看板从“页面宽度比例卡片”改为类似 iOS 小组件的二维占位布局，并让鼠标或触摸触发的换位、尺寸变化具有连续、可中断的空间轨迹。键盘操作保持即时，避免动画拖慢高频无障碍操作。

## 方案选择

采用原生 Web Animations API（WAAPI）与 FLIP 布局动画，不新增 Motion 等运行时依赖。现有布局编辑器已经具备矩形捕获与 WAAPI 动画基础，本次在该边界内升级，不重写持久化或经营组件。

## 布局模型

布局 Schema 升级为版本 3，尺寸枚举改为：

- `1x1`：一个基础列宽、一个基础行高。
- `2x1`：两个基础列宽、一个基础行高。
- `2x2`：两个基础列宽、两个基础行高。

页面使用密集排列的二维 CSS Grid：

- 375px 起的移动端使用 2 列，`2x1` 会占据移动端一整行，这是 iOS 小组件网格的自然结果。
- 768px 及以上使用 4 列，不再存在横跨整个桌面看板的尺寸。
- Grid 容器建立 inline-size container；基础行高根据容器宽度、列数和 gap 计算，使一个网格单位保持正方形。
- 卡片通过明确的 column span 与 row span 占位，DOM 顺序继续作为排序和持久化顺序。

## 组件尺寸约束

每类组件只开放不会破坏内容的尺寸：

| 组件 | 可选尺寸 | 默认尺寸 |
| --- | --- | --- |
| 经营指标 | `1x1`、`2x1` | `1x1` |
| 销售趋势 | `2x1`、`2x2` | `2x1` |
| 库存提醒 | `2x1`、`2x2` | `2x1` |
| 热销商品 | `2x1`、`2x2` | `2x1` |
| AI 饼图 | `1x1`、`2x1`、`2x2` | `1x1` |
| AI 经营报告 | `2x1`、`2x2` | `2x1` |

Contracts 层直接校验组件与尺寸组合，前端菜单从同一份组件注册表读取可选尺寸，避免只在界面隐藏但 API 仍接受无效组合。

## 旧布局兼容

`parseDashboardLayout` 保留版本 1、2 的读取支持，并统一迁移到版本 3：

- 旧 `1/3`：组件支持 `1x1` 时迁移为 `1x1`，否则迁移为 `2x1`。
- 旧 `1/2`、`2/3`、`full`：迁移为 `2x1`。
- 卡片 ID、组件配置和排序不变。
- 读取旧布局后，下一次用户保存时写回版本 3；不新增数据库表或破坏已有记录。

默认布局采用四张 `1x1` 指标卡，销售趋势、库存提醒和热销商品采用 `2x1`，在桌面形成四列模块网格。

## 编辑控件

为保证 `1x1` 卡片在 375px 下可操作，卡片顶部不再同时平铺拖动、上下移动、尺寸和更多操作五组控件：

- 顶部保留紧凑拖动把手、尺寸徽标和更多菜单。
- “上移”“下移”进入更多菜单，仍可通过按钮和键盘访问。
- 尺寸菜单只展示当前组件允许的规格，并使用 `1×1`、`2×1`、`2×2` 文案。
- 拖动把手继续提供可访问名称；状态变化继续通过现有 `aria-live` 区域播报。

## 动效行为

### 换位

1. 状态更新前捕获所有卡片当前的可见矩形。
2. React 完成新布局后，在 `useLayoutEffect` 中先取消旧 WAAPI 动画，再读取无 transform 的目标矩形。
3. 从旧可见位置反向位移到新位置，并动画回到零位移。
4. 快速连续拖动时，每次从屏幕上当前可见位置重新计算，不从上一段动画起点重启，因此不会跳帧。

默认时长为 260ms，曲线使用 `cubic-bezier(0.32, 0.72, 0, 1)`。这是快速起步、柔和收束的 iOS 风格曲线，不增加明显等待，也不使用夸张弹跳。

### 尺寸变化

尺寸切换前同样捕获矩形。目标布局生效后：

- 周围卡片使用位移 FLIP 平滑让位。
- 被调整卡片使用以左上角为原点的 translate + scale FLIP，在 260ms 内贴合新占位。
- 动画只使用 `transform` 与 `opacity`，不逐帧修改 width、height、margin 或 grid 属性。

### 拖动反馈

- 被拖动卡片的内容层轻微放大至 `1.015`，提高阴影并保持足够不透明度，表达“被拿起”。
- 布局位移动画作用于外层卡片，拿起反馈作用于内层面板，避免两个 transform 相互覆盖。
- 鼠标拖动和指针触发的菜单移动使用动画；键盘上移、下移保持即时。

### 减少动态效果

当 `prefers-reduced-motion: reduce` 生效时：

- 跳过位置和尺寸 transform 动画。
- 保留颜色、边框与状态文案变化。
- 排序结果、焦点和 `aria-live` 播报与普通模式一致。

## 异常与边界处理

- 浏览器没有 `Element.animate` 时直接采用最终布局，不阻止编辑。
- 找不到旧矩形、卡片已删除或 DOM 节点已卸载时跳过该卡片动画。
- 连续操作会取消旧动画并从当前可见位置重定向，不累积动画队列。
- 组件尺寸不合法时由 Contracts 拒绝，前端不会保存无效草稿。
- 移动端内容超过组件可用高度时使用组件自身的紧凑展示或内部滚动，不扩大 Grid 行高破坏其他卡片占位。

## 测试与验收

- Contracts：版本 3、组件尺寸组合、默认布局以及版本 1/2 迁移测试。
- 动效单元测试：矩形差值、旧动画取消顺序、快速重定向、尺寸 scale、无 WAAPI 和 reduced-motion 分支。
- 编辑器测试：菜单只展示允许尺寸，旧的“整行”不再出现，上下移动入口仍可访问。
- 响应式测试：375px 为两列单位网格，桌面为四列单位网格；`1x1` 控件不溢出。
- 回归验证：布局读取、保存、并发版本冲突、撤销删除、TypeScript、Lint、构建和 Secret Scan 全部通过。

## 非目标

- 不引入自由拖拽像素坐标或任意宽高。
- 不新增动画库。
- 不改变经营数据 API、AI 查询逻辑或用户隔离规则。
- 不为键盘排序增加延迟或弹簧动画。
