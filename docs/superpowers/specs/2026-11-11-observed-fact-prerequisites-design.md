## Architecture choice

Recommend an **additive versioned observed-facts ledger and authorized temporal reader**. Keep the six connector kinds and existing four-stream bundle unchanged. New typed observations have their own publication receipts and coverage; immutable joined captures select both channels. This preserves historic computations and can carry failure evidence without successful commerce synchronization.

Extending connector kinds/models is possible but propagates new wire variants through fetchers, canonical writers, pagination, dedup and source certification, increasing compatibility risk. Fixture-only MetricInput injection is invalid: it proves neither source persistence nor causal observation and cannot close 031/032.

Freeze `p2-normalized-v1`, `metrics-g4-v1`, existing mock-source-v1/v2 and event-policy-v1 meanings. New namespaces: `observed-facts-v1`, `p2-observed-v1:<sha256>`, `metrics-g4-observed-v2`, `mock-business-observed-v1`, generator `mock-source-v3`. Keep existing six-kind publication runtime transport only where its semantics remain identical; generator-version allowlists must explicitly add v3. P03-031 owns fresh Runtime/BuildJob admission SQL and versioned TypeScript validators. P03-032 extends the real generation-bound interruption and saved-page controls for v3, retaining v2 behavior. Ten deliveries use ten actual restricted delivery attempts, including the old/new-version control, independently of the default replay count. Each v3 generation pins business-model/config hash; never substitute v3 content in old generations. Observed versions are `observed-v1:g:<generation>:e:<sequence>`, separate from connector source versions.

## Write contract and authority

`ObservedFactV1`: full ConnectorBinding (organizationId, workspaceId, storeId, connectionId, externalStoreId), generation, domain, subject, stable factId, sequence, priorVersion/null, sourceVersion, producer/model version, occurredAt, observedAt, payloadHash, strict typed payload. DB assigns recordedAt and receipt linkage. Times UTC milliseconds; windows [start,end), Asia/Shanghai/CNY; quantities safe nonnegative integers, money integer minorCNY, signed deltas explicitly signed, ratios integer basis points, lead/age hours finite nonnegative. Unknown is null with quality reason; empty/zero is observed only with explicit complete measurement receipt. No customer/session identifiers, PII, scenario IDs, hidden batch causes, expected labels or failure-rule configuration enter observations.

Domains:

- FrozenCost(order/line/SKU, quantity, frozenAt, costVersion, unitCostMinor, CONFIRMED/ESTIMATED/UNAVAILABLE); RefundAllocation(refund/order/line/SKU, merchandiseMinor, shippingMinor); ReturnReceipt(receipt/refund/line, acceptedAt, resellableQuantity); Fee(kind, order/null, window, amount, basis, coverage). Reuse existing nullable metric DTO semantics, not nonexistent persistence.
- Traffic(subject STORE/SKU, exact measurement window, visitors/cart/checkout/paidOrders, measurementVersion, coverage); campaign measurement(campaign/day, spend, attributed revenue, eligible/measured counters, interval and attribution-policy version). Store distinct visitor counts cannot be summed across SKUs.
- Listing/Price(SKU, listedAt/status transition, effectiveAt, currency/price version); InventoryLot(receipt/lot, receivedAt, movement quantity and reason, SKU/location); SupplierNotice(notice/purchase order, announcedAt, prior/new ETA, inbound, promised lead hours); quarantine/asOf/safety-buffer observation. Remaining lot quantities come from conserved movements; holding age uses versioned quantity-weighted remaining-lot age, never days-of-cover.
- SyncObservation(job/fence/stream, status, typed error, successfulThrough, watermark, businessObservedAt, transition sequence). No raw provider error text.

`appendObservedPage(grant, fence, binding, generation, publicationId, expectedCursor, pageId, pageHash, records, terminalCoverage)` is a restricted server protocol. Publisher first creates a content-addressed immutable publication/certificate from the pinned model through the authoritative business clock; consumer append verifies that exact publication, live scoped service grant, active generation, lease/fence, cursor and source-chain hash. It must not accept worker-supplied claimed coverage/version as authority. In one transaction validate bounded strict payloads, references/conservation, insert immutable facts and page receipt, advance cursor and terminal completeness. Same page/hash replays return original receipt; conflicting replay, fork/gap, stale fence or cross-generation write fails. Corrections append superseding versions, never UPDATE/DELETE. Future ETA values are allowed only from already observed notices. Future transactions/measurements are excluded.

Capability roles are NOLOGIN/NOSUPERUSER/NOBYPASSRLS; fresh migration uses FORCE RLS, deny PUBLIC/direct writes, fixed-search-path security-definer entry points and runtime login/role checks. Separate publisher, consumer, temporal-reader and definition-provisioner capabilities; no role can self-grant. Authenticate service grants against DB principal, binding, generation, permitted domains and expiry. User reads additionally revalidate live membership and connection. All service expiry, deadline and lease checks use SECURITY_UTC (trusted DB wall clock), independent of adjustable business time. In READ COMMITTED, acquire row locks on current generation, grant and membership in fixed order, recheck under those locks immediately before final append/capture, sample clock_timestamp() at that check, then commit. Revocation/generation reset takes conflicting locks: if committed before final validation the operation denies; if the operation holds locks first it serializes before revocation. A deadline elapsed while waiting denies. Two-connection tests assert both orderings. Caller GUCs alone confer no authority. Migrations grant function capabilities to roles only; operators explicitly provision isolated runtime credentials and scoped grants. Do not grant existing production logins or embed credentials. Missing configuration disables new capability safely.

## Read, capture and failure semantics

`captureObserved({actor,binding,generation,window,visibleAt,domains,comparisonWindows})` and `readObserved({...identity,inputRevision})` return immutable facts, subject coverage, receipt references, authoritative clock revision and source references. At capture, select committed versions whose actual business observation is <= visibleAt and whose publication was available at that capture; effective dates alone never establish visibility. Require current authoritative clock for first capture; historic reads require a previously sealed capture. Backfilled records observed late cannot alter Day3. Once sealed, replay selects its recorded receipt set, not today's canonical rows. Base v1 captures remain current-clock-only; freeze earlier captures before advancing.

Joined revision hashes canonical mapping/model/definition-selector versions, full binding/generation, window/cutoff/clock, base bundle revision and receipts, observed publication/page receipts, selected fact hashes and complete domain coverage, plus comparison capture references. Missing domains stay typed unavailable; incomplete coverage never becomes zero. No whole-store revision may be relabeled as SKU evidence. Bounded overflow returns OVERFLOW, malformed input INVALID_INPUT, stale/fork replay CONFLICT, wrong version VERSION_MISMATCH, out-of-scope opaque NOT_FOUND/FORBIDDEN, unavailable storage SOURCE_UNAVAILABLE. Errors expose no SQL, payload or secret.

Sync failure uses an independent observation capture: successful commerce bundle is optional, not faked. Append actual job transitions in the same committed transaction that records FAILED/SUCCEEDED, sampling authoritative business time even before any page receipt. Map CONNECTOR_FAILED conservatively to TEMPORARY; preserve more specific typed errors only when observed. Recovery appends success; failed page rollback does not erase the later failure transition. A DB outage cannot be silently recorded as success: retain explicit unavailable observation until a real durable retry. Never read `failureRules` to construct event evidence.

## Causal mock model

v3 generates visits first, then cart/checkout/payment transitions. Price and demand interventions change progression probabilities; paid commerce facts and measured traffic originate from that common process. Traffic is never reverse-calculated from existing paid orders. Publish bounded aggregate counters at measurement-window close; measure campaign eligibility/attribution using an explicit deterministic attribution policy and only then certify coverage.

At payment, freeze the then-valid supplier acquisition cost from a versioned cost schedule, not current SKU selling price. Fee charges arise from the fee schedule and actual charge/settlement event; advertising expense links measured campaign spend without double deduction. Refund settlement explicitly allocates merchandise/shipping and line quantities; only accepted resellable return receipts reverse frozen COGS. Null cost remains null. Offline `snapshot.economics` is neither publication input nor runtime oracle.

Listing edges occur at actual launch. Inventory receipts/movements provide real holding history. Supplier notices announce changed promises before delayed receipt, so revised ETA can be known without reading hidden future arrivals. Seed determinism and causal conservation are tested independently of event expectations. Existing v1/v2 generation stays replay-identical.
