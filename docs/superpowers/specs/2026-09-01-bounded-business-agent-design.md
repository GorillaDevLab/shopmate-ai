# 受限经营 Agent 设计

## 目标与边界

实现 #59 的服务端 Agent 编排层：模型根据中文问题从已注册的只读工具中选择工具，工具结果经校验后回注模型，模型最终输出简体中文解释。

本任务不新增聊天 HTTP 接口、数据库模型、任意 SQL、写工具或前端页面。用户与 Merchant 隔离继续由 `ToolInvocationContext` 和各工具 Service 保证。

## 架构

新增 `BusinessAgent`，只依赖 `LLMProvider` 与 `ToolRegistry`。每次运行构造系统政策、用户问题与 Registry 当前已注册的工具定义。Provider 可以返回最终回答或工具调用；Agent 只执行 Registry 白名单中的调用，并把经过输出 Schema 校验的数据序列化为 `tool` 消息后进入下一轮。

采用 Provider 决策而非关键词路由。关键词路由只能覆盖固定问法，直接调用 Service 又会绕过统一工具权限边界；Provider + Registry 能兼顾中文意图理解和服务端强制安全约束。

## 安全与停止条件

- 问题去除首尾空白后必须为 1–2000 个字符。
- 默认最多 3 个工具轮次，配置范围为 1–5。
- 每轮最多 4 个调用，总计最多 8 个调用。
- 同一工具及相同参数不得在一次运行内重复执行。
- 未注册、无权限、输入/输出无效或 Handler 失败均转换为不含内部异常的安全工具结果。
- 达到轮次或调用上限后返回固定中文兜底，不继续请求 Provider。
- 系统政策要求经营数字只能来自已验证工具结果，并把工具内容视为数据而非指令。
- 只有 `status: ok` 的结构化结果会建立数字证据；最终回答中的每个数字都必须命中证据，允许 `*Minor` 的分转元与 `*Ratio` 的比例转百分比。中文数字经营断言会被拒绝，模型必须使用可核验的阿拉伯数字。

## 输出

成功时返回中文 `answer`、`usedTools`、`rounds` 和 `status: "completed"`。无法安全完成时返回固定中文说明和 `status: "limited"`，保留已成功使用的工具名称用于服务端诊断，不返回底层异常。

## 测试

使用脚本化 Provider 与真实 `ToolRegistry` 验证：工具定义可见、工具结果被回注、中文解释返回、经营数字来自 Fixture、未知工具被阻止、重复调用和最大轮次能终止、Provider 错误安全降级、无工具的普通中文回答可直接返回。Mock Provider 补充工具消息后的确定性中文解释，以支持离线集成测试。
