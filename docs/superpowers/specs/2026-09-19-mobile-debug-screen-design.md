# 临时移动端诊断面板设计

## 目标

为手机用户提供不依赖邮箱、AI 或数据库的临时排错能力：当页面可交互时，用户可以打开诊断面板查看并截图；当 React 页面没有成功挂载时，仍然有一个轻量兜底入口显示加载错误摘要。

## 范围与约束

- 仅用于当前排查窗口，默认在移动端显示，可在设置中关闭。
- 不发送网络请求，不读取或展示敏感值，不改动 API、数据库和 AI 调用。
- 采集内存中的错误、未处理 Promise、资源加载失败、当前 URL（脱敏）、设备/视口/构建信息。
- 不读取 localStorage/sessionStorage 的值，只显示键名；URL 查询参数统一隐藏。
- 页面可用时提供“复制诊断信息”和“关闭”操作，提示用户截图发送。
- 页面加载失败时由独立内联脚本创建兜底按钮和面板，避免依赖 React hydration。

## 组件与数据流

1. `layout.tsx` 在移动诊断开关开启时注入内联 bootstrap 脚本。
2. bootstrap 脚本在 React 之前安装监听器，保留最多 60 条脱敏记录，并创建固定定位的诊断按钮。
3. 诊断面板从同一内存快照渲染摘要、错误列表和设备信息；复制使用 Clipboard API，失败时回退到可选文本区域。
4. 应用启动失败、`error`、`unhandledrejection` 或关键资源失败时，兜底入口仍可打开；如果 DOM 创建失败，脚本不抛出二次错误。
5. 设置开关只写入本地偏好；关闭后隐藏入口但保留当前页面诊断监听，刷新后完全停用。

## 交互与错误处理

- 按钮标签为“诊断”，移动端位于右下角并避开安全区；桌面端默认隐藏。
- 面板标题“页面诊断”，显示“请截图发给开发者”，不要求用户填写描述。
- 复制成功显示短暂状态；Clipboard 不可用时显示“请直接截图”。
- 诊断信息为空时显示“暂未捕获到错误”，不能阻止用户截图。
- 所有异常捕获后降级为静态提示，不能影响业务页面。

## 测试策略

- 先添加失败测试：bootstrap 在 hydration 前创建入口、收集错误并生成脱敏快照；复制失败可降级；设置关闭后隐藏入口。
- 运行 web 定向单测，再运行 web 全量测试和 TypeScript 检查。
- 使用生产构建提取内联脚本，在 jsdom 中验证脚本可执行；不调用真实 AI、邮件或外部网络。

## 退出方式

将 `NEXT_PUBLIC_ENABLE_DEBUG_REPORT=false` 重新构建并发布即可移除脚本；已打开的旧页面刷新后消失。该功能不增加服务端配置。
