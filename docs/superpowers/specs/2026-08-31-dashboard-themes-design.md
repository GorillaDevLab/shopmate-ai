# 经营看板双主题与外观设置

## 已确认的方向

用户选择同时保留两套设计，并增加主题切换设置按钮。两套主题共用升级后的经营看板布局，不维护两套页面。

- 暖灰陶土（默认）：暖白背景、石墨灰文字、少量陶土色用于主要操作与趋势图。
- 经典紫色：冷灰白背景与紫色强调，保留原有品牌辨识度，使用相同的新排版和交互。

参考 Anton Skvortsov 的 Watch Shop UI #2 的中性色层次，以及 21st.dev 的 Stats 和 Animated Tabs 的数据排版与选择反馈。参考设计语言，不复制商业图片，不直接执行组件安装脚本。

## 界面升级

1. 顶栏保留品牌与数据来源，右侧增加有文字标签的“外观设置”齿轮按钮；375px 下仍可使用。
2. 收紧标题层级，将 7 天、30 天、自选时段组织为清晰的分段工具栏。保留原有日期校验、应用和取消行为。
3. 指标卡突出金额、等宽数字、涨跌文字和比较周期；减少装饰圆点及重阴影。不添加 API 未提供的迷你走势图。
4. 销售趋势保留真实日数据、坐标和键盘选择，精细化线条、选中点与金额反馈；颜色随主题变化。
5. 库存提醒使用紧凑列表、分隔线、库存及预测文字，减少嵌套卡片。热销商品采用对齐排名行，突出销量和销售额。
6. 加载骨架、空态、错误与重试按钮同步适配主题，涨跌及库存风险始终保留文字含义。

## 外观设置交互

- 点击按钮打开小型原生对话框，展示两张配色预览及中文主题名称。
- 使用原生单选组，支持 Tab、方向键和可见焦点；打开时焦点进入，Escape 或关闭按钮退出并回到触发按钮。
- 选择立即生效，不需要保存按钮；说明“仅保存在当前浏览器”。关闭不撤销已选择主题。
- 本次仅有两个浅色主题，不增加深色模式、跟随系统、字号设置或账户同步。

## 技术与安全边界

- 保持 React 19 / Next.js / Tailwind 4，不引入主题框架或大型动画依赖。
- 全局 CSS 语义变量定义背景、表面、文字、边框、品牌、淡色底、焦点及阴影；替换图表点光晕、排名底色等硬编码颜色。
- `html` 的 `data-theme` 仅允许 `terracotta`、`purple`，主题组件只负责外观，不包裹或重新挂载数据请求组件。
- 浏览器存储仅保存主题标识，不保存 Token、密码或业务数据。读取值校验白名单；非法值回退默认。
- 首次绘制前恢复有效偏好，避免刷新先显示错误主题；禁止将存储原文拼接到脚本或 CSS。
- 存储不可用时仍可在当前页面切换，并显示具体提示“当前浏览器无法保存外观设置，刷新后将恢复默认主题”。初始化读取失败安全回退。
- SSR 输出与客户端恢复协调，避免 hydration 报错；初始化脚本由固定代码构成，不放宽现有安全策略。
- 尊重减少动画偏好，过渡仅用于必要选择反馈，不给数据变化添加误导性数字动画。

## 保持不变

不修改 API、认证、数据库、商家隔离、指标计算或接口契约。切换主题不发起业务请求，不改变日期、金额或趋势选中日期。

7/30 天与自选 1–31 天继续整页联动，历史库存仍标明当前快照。保留请求取消与防过期覆盖机制，以及加载、空、错误和真实重试路径。

## 验收与验证

- 单元测试覆盖默认主题、两向切换、有效偏好恢复、非法偏好、读写失败提示及设置关闭行为。
- 浏览器检查两套主题所有主要区域，刷新后选择保留，无错误主题闪烁及 hydration 错误。
- 核对切换前后 API 请求次数、日期、指标金额和趋势选中点不变；回归 7/30/自选与错误重试。
- 375px 无横向溢出；1440×900、1920×946 在现有演示数据下尽量维持一屏，不能隐藏真实内容来满足高度。
- 两套主题分别截图，检查焦点、中文长标题、图表轴线、空值、风险和涨跌对比度。普通文字目标对比度至少 4.5:1。
- 运行前端测试、TypeScript、Lint、生产构建；避免构建与现有开发进程输出冲突。

## 方案审查

已核对主题切换与日期筛选互不依赖、库存语义不变、存储失败降级和移动端交互边界。设计待用户确认，尚未实施业务代码改动。
