## Global constraints

- Each full function/callback/test callback/SQL function is fewer than 40 physical lines, including its header and body. TypeScript has no `any` or suppressions.
- Validate external and port boundaries; authenticated current membership/store scope, parameterized SQL, immutable scoped evidence and explicit version/hash/revision binding.
- Security deadlines use SecurityClock and a real, live AbortSignal; no BusinessClock substitution. Late provider results cannot publish after fallback.
- Keep PRIMARY and SHADOW authority separate. Default production registry contains Rules only; no vendor raw payload, scenario oracle or secret is persisted.
- No real Jev/LLM/merchant/notification network calls, production deployment or online migration. Existing deployment workflow remains paused. No workflow/billing/access changes.
- One `feat/` branch and PR per card, granular independent commits, focused tests and relevant types/build/lint/format checks. Independent task review and strongest final review precede publication; latest exact PR-head six product CI checks precede self-merge. Preserve branches and worktrees.
- Existing assignees are preserved. Shared Prisma, database-index, tenant runner/config and app-module files have one exclusive owner at a time. The explicitly requested batch uses isolated workers; do not take another person's active work.
- Fixture completion does not satisfy runtime gates. Never mark blocked integration/scenario tasks Done using fake audit/outbox or an in-memory substitute for PostgreSQL races.
