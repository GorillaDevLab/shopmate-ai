# P09-004 transactional audit writer implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development. Do not claim or implement until P09-002/003/005 are actually merged and the live card is Ready/unassigned.

**Goal:** Append strict redacted tenant audit entries in the caller's existing transaction and append anonymous authentication events through a separately selected server-side sink.

**Architecture:** The API-local writer consumes AuditRedactor and hashAuditEntry. It uses the database's organization lock/head and RLS rather than duplicating sequence authority. The caller creates trusted transaction handles after opening READ COMMITTED, binds current scope/identity, owns lifetime and rolls back on writer failure; no internal pool, BEGIN or COMMIT.

**Tech Stack:** Existing contracts, TypeScript, node:crypto/node:util, Vitest and parameterized PostgreSQL client; no new dependency.

## Ownership and consumed interfaces

Own only apps/api/src/audit/audit-append.repository.ts and audit-append.repository.spec.ts. Existing shared AuditAppendPort<TTransaction,TSecuritySink> returns TenantAuditEntry/AnonymousAuthSecurityEntry. No shared DTO/index edits.

- `new AuditRedactor().redact(unknown)` -> readonly `{redactionVersion:1,event:AuditAppendInput}`. Dispatch only through the explicitly invoked method, never an optional body scope.
- `hashAuditEntry(unsigned: unknown):string` accepts exact Omit<TenantAuditEntry,"entryHash">; domain recipe is already exported by audit-hash.ts. Reuse it. No second canonicalizer/hash recipe or persisted-envelope redactionVersion field.
- `public.audit_chain_head(org,workspace,store)` -> sequence bigint/entryHash|null, genesis0/null. It holds the per-org xact lock and freshly rechecks authority. audit_logs has quoted auditId/fullscope/actorId/actorKind/requestId/occurrenceId/sequence/prevHash/entryHash/hashVersion1/redactionVersion1 and exact TenantAuditEvent payload. See P09-003-implementation-report.md and fixreport for final helper roles.
- Ordinary tenant writer SELECT/INSERT, no UPDATE/DELETE. Anonymous writer has INSERT on auth_security_events(auditId,payload), **no SELECT**. Therefore anonymous INSERT MUST NOT use RETURNING; PostgreSQL RETURNING requires read privileges. Confirm affected-row count and construct the validated entry from its generated ID/event. Do not broaden grants to make RETURNING work.

## New API-local seams

```ts
type AuditTenantScope = Readonly<TenantAuditEvent["scope"]>;
type AuditActor = Readonly<TenantAuditEvent["actor"]>;
interface AuditTransactionClient {
  readonly query: (sql: string, parameters?: unknown[]) => Promise<{
    readonly rows: readonly Record<string, unknown>[];
    readonly rowCount: number | null;
  }>;
}
interface BoundTenantTransaction {
  readonly kind: "TENANT";
  readonly client: AuditTransactionClient;
  readonly scope: AuditTenantScope;
  readonly actor: AuditActor;
  readonly isActive: () => boolean;
}
interface BoundAuthSecuritySink {
  readonly kind: "ANONYMOUS_AUTH_SECURITY";
  readonly client: AuditTransactionClient;
  readonly isActive: () => boolean;
}
```

These are trusted server-only owner handles, not HTTP schemas or proof that arbitrary caller-supplied metadata authenticates a user. They cannot be accepted from request body. Existing database pool.connect returns a real pg PoolClient with rowCount; no pg dependency is needed in API to describe this structural boundary. EventTransactionClient's narrower rows-only type alone cannot confirm an anonymous insert. P04-029 supplies actual open transaction/lifetime and verifies current membership in that same unit. USER actor is actual bound principal; SERVICE/SYSTEM actor comes from server grant mapping and must not impersonate its human authorizer. Database rechecks all authority.

Export `AuditAppendRepository` implementing the existing shared generic port and a fixed payload-free `AuditAppendError` domain code. Constructor may accept a test-injected audit ID factory defaulting to randomUUID. Validate generated IDs. Scope/actor and parsed input are snapshotted before asynchronous queries. Reject inactive/mismatched domain/scope/actor handles before SQL. Never attach raw input, parser issues, SQL detail or arbitrary cause to public errors.
