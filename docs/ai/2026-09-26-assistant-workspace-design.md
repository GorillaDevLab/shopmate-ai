# ShopMate AI 统一经营助手与聊天工作区

日期：2026-09-26

状态：用户已认可功能与 UI 方向；本文完成代码调研与自查，等待书面方案确认后编写实施计划。

## 目标与边界

继续使用现有 DeepSeek 配置，不承诺与 Codex 模型能力完全相同。交付目标是让用户自然提问、连续追问、看到真实执行进度，并在同一对话里生成图表和确认加入看板。

本轮同时升级统一对话机制和 UI，不只换样式。验收不用真实 AI、生产数据库、外部收费服务。不能把未实测的真实模型效果写成已验证。

第一版会话历史保存在当前浏览器，刷新和在看板与完整聊天页之间导航后可恢复；不支持跨设备同步。退出登录清理本地经营对话；服务端确认登录身份后才能加载对应记录。浏览器存储不是可信经营证据。此方案不需要数据库迁移。

不包含图片/文件上传、语音、模型切换、自动修改订单或库存、后台持久任务、跨设备历史、任意 SQL。不得放置没有实际功能的按钮。

## 当前代码证据

- `apps/web/src/app/chat-session.ts` 每次调用创建自己的 React 状态，保存最近 6 轮文本及最近图表查询，缺少共享会话仓库。
- `/chat` 与 `DashboardAiAssistant` 分别调用该 hook，切换入口不会共享当前会话。
- `assistant-intent.ts` 和右侧助手承担部分自然语言分流，完整聊天页不具备相同的图表链路。
- `ChatPending` 明确只有计时等待信息；`AiChatController` 当前返回完整 JSON，没有工具进度事件。
- `LLMProvider.generate` 及 DeepSeek 客户端包装没有贯通调用取消信号。
- `BusinessAgent` 已有有界工具循环、权限过滤和已验证数据检查，应复用而非绕过。
- `DemoAuthController` 只有登录/退出，需新增受保护的身份读取接口以隔离浏览器历史。
- PR #187 的数字展示校验修复目前仍独立开放；实施前检查是否已合并，避免覆盖或重复提交。

## 方案比较与选择

1. **推荐：统一对话执行 + 共享浏览器会话 + 真实进度流。** 解决两个入口行为不一致和连续追问问题，无数据库部署依赖；代价是不支持跨设备历史。
2. 仅重做聊天样式。改动少，但无法解决上下文丢失、工具分流和执行过程不透明，不满足本轮目标。
3. 服务端持久会话与任务队列。能支持跨设备恢复和后台任务，但需要数据库迁移、作业生命周期及更复杂的部署。本轮不采用。

## 用户流程与验收对话

“最近经营怎么样？” → 查询默认周期的经营数据并解释 → “哪家店表现差？” → 沿用当前日期和指标查询门店 → “为什么？” → 用可用订单/商品证据解释，无法证明原因时明确区分推测与事实 → “画成柱状图，只看北京” → 查询明确匹配的门店并生成预览 → “放到看板” → 展示加入确认操作，用户点击后加入草稿，完成并保存后才持久化。

不要求用户填写内部 ID。名称有歧义时只问必要澄清问题；不得擅自选择同名门店。无匹配项、没接入渠道、空数据和无权限分别说明。

“只看北京”的解析使用当前商家受限门店目录，不推断不存在的地域字段。明确日期优先于旧上下文；新建对话不继承旧会话的门店或图表。

## 架构与数据流

### 统一执行入口

新增版本化的助手执行入口，前端两个界面都使用相同客户端和协议。旧 JSON 聊天及图表查询端点保留兼容，不因新增协议删除现有商品文案、图表或看板功能。

后端复用 BusinessAgent 工具循环：读取数据、返回解释、提议图表都是同一执行链路。新增受限图表工具，输入沿用查询协议，输出由现有执行器验证并生成结构化结果。前端不通过“销售额”“门店”等关键词选择付费 API。明确点击图表类型按钮只在已有数据和允许的视图范围内切换，不重复调用模型。

前端请求包含请求 ID、有界历史、当前查询上下文；merchantId、userId、权限只从认证上下文取得，不能接受客户端覆盖。前端本地记录仅用于消解指代；数字结论必须来自本轮验证结果。结构化计算在程序中完成，不交给模型随意运算。

会话上下文明确保存最近日期范围、门店选择、指标和图表查询；旧结果显示查询时间，不能冒充实时数据。需要新事实时重新查工具，不因“沿用上下文”直接信任客户端数值。

### 真实进度与停止

采用受保护的 POST + fetch 可读流，事件类型有 `accepted`、`tool-started`、`tool-completed`、`composing`、`completed`、`failed`；每个事件携带请求 ID，前端只消费当前请求事件。

进度来自实际工具/模型阶段，用户看到“正在查询门店销售”“正在整理回答”；不显示虚构推理、百分比或内部 chain-of-thought。不把模型未经校验的 token 直接展示；完整回复通过校验后才发送完成事件。

AbortSignal 从前端贯通到 API、Agent 和 DeepSeek HTTP 请求。停止后不开始新工具调用、不写入迟到回复、不自动重试。已经执行的只读数据库查询不承诺可中断；已经提交的模型调用可能已经计费，UI 不承诺停止能撤销费用。

路由切换或收起面板不取消请求，由顶层会话控制器管理；退出登录、确认删除执行中的会话及用户点击停止会取消。相同会话最多一个执行；第一版同一浏览器工作区一次只运行一个请求，其余会话可以浏览但发送禁用并提供返回运行会话入口。

断流/页面刷新不自动重发付费请求，显示“连接中断，结果尚未确认”。请求 ID 用于当前进程内的重复提交保护，不声称跨实例或服务重启具备全局 exactly-once 保证。保留现有工具次数和总轮次上限，不增加自动模型纠错次数。

### 会话仓库

顶层客户端 Provider 提供会话列表、当前会话 ID、草稿、消息、图表附件、请求状态与 AbortController；两种 UI 只负责展示和操作。

受保护的身份接口返回当前 userId/merchantId 所需的最小信息，浏览器存储按这两个维度隔离。首次加载、身份切换及收到 401 时先隐藏会话数据，验证身份后再恢复；退出时取消执行并清除对应经营历史。身份和权限不能从本地存储恢复信任。

版本化存储通过 Zod 校验，限制最多 30 个会话、每会话最多 100 条消息，总序列化体积最多 2 MiB。到达上限时明确提示清理或新建，不能悄悄丢掉正在发送的内容。存储不可用/配额失败时保留内存对话并提示“历史暂未保存到此设备”。模型上下文继续按完整问答轮次截断，不发送所有历史。

新建、重命名、切换、删除会话；标题默认从首个问题本地截取，不单独调用模型。删除二次确认。输入中的草稿属于各自会话，切换回来恢复。失败/停止消息不进入已完成工具证据。

## UI 设计

### 完整聊天工作区

- 保留 ShopMate 导航和冷静/灵动主题；聊天区域内左侧约 240px 会话栏，中间是阅读区和底部输入区。
- 消息文本阅读宽度约 760px；图表和宽表格可以扩展但不得撑破页面，表格单独横向滚动。
- 空状态使用清晰标题和少量经营问题建议；发送后建议卡片收起，不一直占据输入区。
- 助手正文不包在大块高饱和气泡中；用户消息保留轻量气泡，标题、段落、列表、数字和图表层级一致。
- 商品文案保留为可展开的工作流入口与结构化结果，不再在聊天页顶部常驻占据大面积。
- 状态明确区分加载会话、空会话、等待响应、停止、失败和历史保存失败。

### 看板右侧助手

- 默认宽度约 520px，可在桌面拖动调整，范围 380–900px 且不能超过当前视口；提供键盘可操作的调整方式。
- 保留收起和打开完整聊天入口；跳转继续同一会话、同一草稿及执行状态。
- 大屏不使用遮罩阻止查看看板；窄屏转全屏，不能出现横向溢出。
- 拖动时只改布局，不触发查询、重复发送或刷新图表。

### 输入、移动端和可访问性

- textarea 从 2 行自适应，最大约 180px 后内部滚动；Enter 发送、Shift+Enter 换行，中文输入法 composition 期间 Enter 不提交。
- 请求中发送按钮切换为停止；不添加不可用的附件、语音、模型选择按钮。
- 375px 起可用，手机全屏，会话列表用抽屉，输入区适配软键盘和安全区域；使用兼容 iOS 16.2 的 API 与现有非安全 HTTP UUID 降级。
- 用户滚动阅读旧消息时不强制拉到底部；底部有新消息时提供返回最新位置按钮。
- 所有操作有可访问名称与焦点态；触控目标至少 44px；适配 reduced-motion，动效只作用于面板/状态转换。

## 安全与异常处理

所有请求、流事件、历史存储、查询和工具输出使用严格 schema。模型与历史都不构成权限来源；工具权限、商家过滤和参数化查询不变。Markdown 不执行任意 HTML，不新增危险 URL 或脚本能力。

客户端不保存 Token，不记录完整模型提示词、业务原文或敏感认证数据到诊断日志。只记录请求 ID、阶段、耗时、脱敏错误分类。401 引导重新登录，403 才表示实际授权不足，模型配置/限流/超时/数据校验错误分别呈现。

进度流响应设置 no-store；代理仅对该 API 路径关闭缓冲并配置合理超时，不改变静态资源或其他 API 的鉴权。流中失败用协议事件表达；首个事件前失败仍用准确 HTTP 状态。旧客户端不强制自动回退重发请求。

## 验证与交付

1. 协议测试：历史有界、事件顺序、错误和取消终态、未知字段拒绝。
2. Agent 模拟集成：自然提问、连续追问、日期继承/覆盖、图表提议、无匹配/空数据/歧义、无权限、数值真实性、用户停止后无后续工具调用。
3. 前端测试：共享会话、刷新恢复、账号隔离、401 清理、存储失败、新建/重命名/删除、输入法、多行输入、停止、迟到响应丢弃、复制降级。
4. 浏览器隔离测试：拦截所有 AI/生产数据请求；桌面/375px、冷静/灵动、长文/宽表/图表、面板拖动、聊天页切换、手机软键盘布局。不得通过现网 AI 接口做验收。
5. contracts/API/web 单元测试、类型检查、lint、生产构建和现有 iOS 客户端兼容性扫描；逐步记录真实结果，不把模拟模型测试写成真实模型质量评估。
6. 前后端和 contracts 一起发布；提供流代理配置说明、旧端点回滚路径及不付费的 smoke 方法。不执行生产部署或数据库修改。
