# Server-derived sync runtime bootstrap

1. Scope: the P2 runtime plan's restricted database identity and metadata foundation. No independent sync process, provider composition, deployment or online migration is included.
2. Input: the dedicated sync login supplies one bounded grant ID. Caller identity GUCs, tenant/store selections and targets do not determine the returned binding.
3. Derivation: `sync_host.runtime_bootstrap(TEXT)` returns the current grant principal, merchant, complete source scope, session configuration/hash/version, initial sync boundary and actual business clock/revisions.
4. Readiness: `WAITING_RUNTIME` carries a null runtime opening; `READY` requires a current-generation Runtime matching the complete scope and exact frozen configuration. Neither state claims publication or successful synchronization.
5. Authority: the RPC requires a safe dedicated login, its exact active grant, current VIEWER workspace membership, active merchant/connection, current generation, demo tenant and DEMO environment marker. Unknown, foreign, invalid, revoked or replacement bindings return null.
6. Concurrency: a valid owned descriptor determines the control lock. A VOLATILE fresh lookup after a real lock wait rechecks the grant and current authority. The existing control protocol remains mandatory; no permission result is cached.
7. Permissions: the guarded RPC uses the existing sync RPC definer pattern with fixed `pg_catalog` search path and schema-qualified tables. Its private invoker lookup is not executable by workers or PUBLIC. Workers receive only RPC EXECUTE, with no direct DemoSession/Runtime SELECT or elevated role grant. SET ROLE delegation is rejected.
8. SDK: `SyncWorkerPorts.connectGrant(grantId)` derives its identity before establishing existing grant-bound worker GUCs, then verifies current work on the same pinned backend. `runtimeBootstrap()` recomputes current metadata; existing explicit-binding SDK callers remain compatible.
9. Validation: the SDK checks the closed descriptor, full scope, clocks, canonical owned configuration hash and generator version. READY opening must match the validated configuration. Returned scope and nested configuration are frozen.
10. Verification: real restricted PostgreSQL fail-first tests cover configured/actual Runtime states, forged caller identity, foreign/malformed grants, membership/production denial, private function ACLs, real lock-wait revocation, generation reset, grant-only SDK identity and current revocation. Existing SDK regressions remain enabled.
11. Delivery: migration plus SQL tests, grant-only SDK plus focused input/integration tests, mandatory tenant CI registration and this report are separate commits. Exact-head full CI and independent review remain required before merge.
12. Remaining P2: pure connector composition, a common published target, the bounded durable sync process, interruption/replay scenarios and full-profile source-to-sync acceptance. A bootstrap descriptor cannot advance a sync job or assert downstream freshness.
