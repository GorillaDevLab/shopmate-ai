## Design decisions and rationale

### One functional unit, three tables

This unit is useful before a generator exists: tests or a future worker can claim, durably append validated source states, survive process recreation/ack loss and publish/read an immutable certificate. No empty future scan table or placeholder port is needed. Head is derived from max PUBLISHED revision. Own-certificate joins remain mandatory even though the current no-hole rule also stops a later revision from publishing around an open one; the reader boundary must stay correct if future operator recovery permits a hole.

### Snapshot events make the first codec complete and bounded

The currently shared CommerceConnector exports exactly store/product/order/refund/inventory/marketing state records. A fixed snapshot event union maps all six without prematurely designing a general-purpose business event language or persisting the old simulator's private future plan/economics as consumer truth. One business transition may need several events, and a bounded chunk commits their accepted records and projections together. Version1 does not claim cross-event causal closure or economic conservation. The eventual generator must persist observable facts and test those semantics; changing accepted event codecs later requires an explicit new version, not opaque extra keys.

A database-derived one-entry manifest is deliberate. It completely enumerates the physical projection obligation of each event and prevents a worker from declaring an empty manifest while storing a visible fact. It also removes a second, caller-controlled copy of each projection payload. Inventory and campaign keys are tuples to avoid delimiter collisions. Stable phase rank and tuple order settle same-time ordering; chronological generator semantics must emit in that order. An unpublished checkpoint is private progress: it may stop midway through any timestamp, including targetTime, then continue by a strictly increasing lastEvent tuple. Only the sealed PUBLISHED certificate exposes completeness through targetTime INCLUSIVE. First-job events include openingAt; later jobs require events strictly after the prior published inclusive frontier. This initial boundary matches materialize's <=at semantics without another protocol version or clock advance. Future same-clock command writes separately require requestRevision and the explicit receipt-backed same-tick chronology exception described in the brief.

Preserve SourceScope.externalStoreId validation exactly in the codec, including its 200 JavaScript UTF-16-unit limit and unnormalized identity. A blanket 200 UTF-8-byte limit would reject already-valid Chinese namespaces, while NFC coercion would merge distinct identities. Only generated non-store IDs receive the explicitly narrower byte bound; normalization belongs to CommerceText. Real-login Chinese/NFD/supplementary-character acceptance is part of this unit's verification.

### Atomicity without a fourth receipt/chunk table

The latest committed receipt is enough to disambiguate the immediately retried call after an uncertain acknowledgment. It remains through renew/fail/takeover; a current lease can compare its old expected checkpoint plus next proposal and exact stored event/version envelopes. Older-than-latest retries report CONFLICT. No attempt is made to magically replay transactions or claim a changed payload succeeded based only on a matching checkpoint hash.

Normal guards alone do not prevent an INSERT followed by COMMIT without a checkpoint update. Indexed deferred fact checks require every new sequence to be included in the committed checkpoint and to have its exact version. A BuildJob mutation verifies the newly appended range once and records its receipt. The DB-derived transaction ID prohibits two job mutations in a transaction, preserving one bounded append boundary without using a forgeable caller setting as evidence. Deferred checks additionally catch trigger-suppressed mandatory operations. Legitimate empty frontier advancement is supported; a declaration of nonzero events cannot silently degrade to empty when rows are suppressed. An authorized dishonest generator can still declare an empty interval, which is the explicit semantic-completeness boundary.

### Lease and revocation boundaries

LeaseOwner/fence/grant all match, expiry comes from database wall clock, and renew/reclaim require separate transactions. A stale fence cannot regain authority through a receipt. Publication retries are read-only against an already immutable certificate, so their old wall expiry is irrelevant while current access and matching publication identity remain required.

Leases are rechecked by the final database guard, including deferred constraints; there is no impossible guarantee that the wall clock cannot tick between a final guard and the physical commit record. CONTROL remains held until transaction completion, so a later claimant/control cannot modify the same session through the supported protocol before that transaction releases it. Revocation has no global AUTH lock: the fresh post-CONTROL authorization check is the documented authorization point; later failed checks roll back, but an overlapping later revocation need not wait for an already-authorized transaction to finish.

### SQL/role correctness details to preserve during review

- BEFORE STATEMENT source guards must acquire CONTROL before uniqueness/row work; BEFORE ROW guards need their own fresh authorization command. Merely marking a wrapper VOLATILE without a separate fresh SQL command is insufficient.
- Worker triggers use only SELECT on authorized source/auth rows plus narrow existing DML rights. No source SELECT FOR UPDATE/SHARE of control/auth rows, hidden admin connection, SECURITY DEFINER, or reader access to event/checkpoint fields.
- Reader BuildJob policy references only its own row/current access. EntityVersion joins BuildJob, so no RLS policy recursion is introduced. The grant includes certificate columns plus state used by the join and never SELECT \*.
- `pg_current_xact_id()`/xid8 is server-derived persistent metadata; Prisma models it as Unsupported when necessary. No caller-supplied transaction ID or GUC proves a mutation already happened.
- PostgreSQL built-in sha256(bytea) avoids pgcrypto. JSONB text and canonical UTC construction define hashing; JavaScript stringify is not claimed equivalent. Hashes never replace full envelope equality on idempotent retry.
- SQL JSONB byte/depth/node/shape/numeric checks mirror TS constraints. No dynamic SQL identifiers or caller-supplied expressions exist. Validation exceptions are translated to fixed SQLSTATE messages.
- Runtime's additional composite unique key is schema support only; it does not add mutable state or privileges. Composite FK uniqueness must be present on exact referenced columns, including SourceEvent full scope/releaseRevision/eventSeq.
- Database physical proof can check a declared manifest and stored counts, not prove a generator omitted no business fact. Financial fields are deterministic bounded minor-unit integers with contract equations, not an oracle or a prediction.

## Closed codec and deterministic manifest

Use codec `source-snapshot-v1`. Each input event is EXACTLY `{kind, occurredAt, ordinal, after}`. kind is STORE|PRODUCT|ORDER|REFUND|INVENTORY|MARKETING; occurredAt is canonical UTC ISO with exactly milliseconds; ordinal is a canonical bigint decimal string. after is the corresponding current ConnectorStore/Product/Order/Refund/Inventory/CampaignMetric record from `packages/contracts/src/commerce/connector-data.schema.ts`, with the restrictions below. There is NO arbitrary metadata, private economics, scenario/decision/expected-answer field, SQL identifier, callback or tombstone. Product DELETED is its existing explicit status. One business change can emit multiple ordered snapshot events in one chunk (e.g. ORDER + INVENTORY); the generator must eventually enforce causal/financial conservation across them.

Exact mapping (phase ranks fixed; key is the JSONB array's database text, COLLATE "C"):

| kind      | phase | entity key tuple                                 | record schema                 |
| --------- | ----: | ------------------------------------------------ | ----------------------------- |
| STORE     |     0 | ["STORE", externalStoreId]                       | ConnectorStoreSchema          |
| PRODUCT   |    10 | ["PRODUCT", externalProductId]                   | ConnectorProductSchema        |
| ORDER     |    20 | ["ORDER", externalOrderId]                       | ConnectorOrderSchema          |
| REFUND    |    30 | ["REFUND", externalRefundId]                     | ConnectorRefundSchema         |
| INVENTORY |    40 | ["INVENTORY", externalSkuId, externalLocationId] | ConnectorInventorySchema      |
| MARKETING |    50 | ["MARKETING", externalCampaignId, date]          | ConnectorCampaignMetricSchema |

Event chronology is `(occurredAt,phaseRank,entityKey COLLATE "C",ordinal)` strictly increasing across chunks and revisions. Equal tuples are the same event identity. DB derives eventId = SHA256(JSONB text of `{codec:'source-event-id-v1',scope,kind,occurredAt,entityKey,ordinal}`), where scope has all seven SourceScope fields and ordinal is a JSON string. DB assigns dense eventSeq; callers never allocate it. Duplicate IDs in a new append conflict; an identical retry of the latest committed chunk is a no-op consuming no sequence. Mixed previously accepted events + new events are deliberately CONFLICT, not partial acceptance.

All after.externalStoreId equal scope.externalStoreId. Input after.source.version must be null; source.updatedAt must equal occurredAt (the source protocol has reliable change time). DB replaces version with `mock-runtime-v2:g:<generation>:e:<eventSeq>` in stored payload and projection. The remaining source.quality and nullable values retain current Connector semantics; partial records are supported. Retry comparison reconstructs this same derived version for the saved sequence. Never compare incoming null with a stored derived source version directly.

Exactly one version per event. The database derives manifest `[{kind,entityKey,eventSeq,versionHash}]`; eventSeq is a JSON string. EntityVersion payload equals the event's complete stored after record, byte semantics = JSONB equality. versionHash hashes `{codec:'source-version-v1',scope,releaseRevision,eventSeq,kind,entityKey,occurredAt,payload}`. SourceEvent envelopeHash hashes `{codec:'source-envelope-v1',scope,releaseRevision,eventId,eventSeq,kind,phaseRank,entityKey,ordinal,occurredAt,payload,manifest}`. No caller manifest/hash is accepted as proof. All sequence/revision/ordinal fields in hash JSON are strings; generation/phase are integers. Dates in hash envelopes are the canonical UTC strings, not session-dependent timestamp casts.

Hash function is `encode(pg_catalog.sha256(pg_catalog.convert_to(value::text,'UTF8')),'hex')` over a database-constructed JSONB object. No pgcrypto/new extension; do not reproduce PostgreSQL JSONB formatting with JSON.stringify. ConfigHash retains its existing independent recipe. Compare full envelopes/payloads as well as hashes on retries; hashes are correlation/integrity evidence, not authorization.

## Current inclusive read boundary and future same-clock writes

This unit deliberately delivers a read-only source BUILD protocol driven by clock advance; it does NOT yet enable command writes/read-back. Its initial PUBLISHED certificate already includes events at targetTime=clockNow, so the next SQL adapter can preserve current materialize's occurredAt<=at behavior on a freshly published current clock. Apply the inclusive predicate directly; no successor timestamp, AFTER_TICK/AFTER_MAX protocol, 1ms advance or sentinel migration is required to make initial reads usable. An inclusive cutoff C is physically covered when C<=certificate.processedThrough; a later cutoff remains lagging/unavailable rather than silently capped. This also handles the supported maximum calendar timestamp without overflow. Connector replacement itself remains a separate unit.

Unchanged-clock command writes remain a genuine later extension: after a certificate publishes, unchanged clockNow makes claim IDLE, UNIQUE(sessionId,generation,targetClockRevision) forbids another job for that clock revision, and the next job's occurredAt>previous PUBLISHED frontier rule closes the tick to later events. Thus v1 cannot integrate a new price command accepted at the same clock after publication. Do not advertise Phase8 write verification as completed by this persistence unit.

Concrete Phase8 prerequisite (separate migration/unit, no implementation here): add a durable monotonically increasing requestRevision independent of clockRevision, incremented under CONTROL for each accepted source mutation or clock request together with its durable command receipt. Jobs freeze targetRequestRevision and target business clock; uniqueness/idleness use requestRevision, replacing the clock-only unique/IDLE rule. Keep clockRevision as metadata. An open job finishes its frozen request prefix; the next revision can publish a higher request prefix at the SAME business timestamp. Its certificate pins requestRevision plus the already-inclusive targetTime, so earlier certificates remain immutable and exclude later same-time writes by sequence/request pin.

That future migration must also extend chronology/time guards explicitly: order same-time events by (occurredAt,requestRevision,phaseRank,entityKey,ordinal), and allow newly accepted higher-requestRevision command events at the previous published target tick. Replace the current occurredAt>baseProcessedThrough condition only for that receipt-backed same-tick case; continue rejecting arbitrary earlier timestamps and any mutation to accepted events. Coverage then means all accepted events in the frozen request prefix through the inclusive business target, not that no future command can share that timestamp. Keep one open job/no abandonment and CONTROL/fence/own-certificate checks. A write may return ACCEPTED while publication is pending; committed/verified source success requires its durable certificate, and immediate read-back must require a certificate with requestRevision>=the command receipt. Do not fabricate timestamps, advance the clock by1ms, rewrite clockRevision or regenerate full history synchronously.

Boundary gates for THIS persistence unit: first-job events exactly at openingAt and targetTime are valid; multiple target-time tuples can span private unsealed checkpoints; new events at a previous PUBLISHED frontier are rejected; a sealed certificate at F covers an inclusive cutoff C=F; target=max calendar remains valid without arithmetic overflow. Future adapter conformance must include an event exactly at cutoff in both materialize and SQL results. Deferred Phase8 gates: two accepted price mutations at unchanged clock yield increasing request/publication revisions, immediate read-back after committed/verified success sees the latest price, and the earlier pinned certificate remains unchanged. These future write gates do not expand this unit's schema or ports.

## Exact database shape

All three tables carry full scope `(organizationId,workspaceId,storeId,sessionId,connectionId,externalStoreId,generation)` and a full-scope FK to Runtime; add only the required composite UNIQUE on Runtime, without granting mutations. PKs may use sessionId/generation because Runtime's full binding is immutable, but every child FK/check/policy must verify full binding. All FKs ON DELETE RESTRICT ON UPDATE NO ACTION. No SQL enum dependency needed: checked TEXT is sufficient.

BuildJob:

- PK(sessionId,generation,revision bigint>0); UNIQUE(sessionId,generation,targetClockRevision); partial UNIQUE(sessionId,generation) WHERE state IN ('BUILDING','FAILED'). Full binding+revision UNIQUE for child FK.
- immutable targetClockRevision int32, targetTime, baseRevision bigint>=0, baseHighEventSeq bigint>=0, baseProcessedThrough, createdAt. Copied/derived in INSERT trigger from the fresh locked session and current max PUBLISHED certificate, never from caller. revision=head.revision+1 or1; baseRevision/headHigh=0 without head; baseProcessedThrough=Runtime.openingAt without head. Target=session.clockNow with its clockRevision, never baselineEnd/max(...). No Runtime=>claim UNINITIALIZED; clockNow<openingAt=>IDLE; no open job and existing published target>=clockNow=>IDLE. First target==openingAt may produce a physically valid empty certificate.
- state BUILDING|FAILED|PUBLISHED; leaseGrantId, leaseOwner canonical lowercase RFC4122 version4 UUID text, fence bigint>=1, leaseUntil; failureCode null|INTERRUPTED|GENERATOR_INVALID. These codes are worker diagnostics, not arbitrary messages. Fixed lease is clock_timestamp()+30 seconds on claim/renew; callers cannot choose wall expiry. On FAILED preserve last lease fields and checkpoint, clear no facts. Takeover always increments fence, including FAILED; a FAILED job is immediately claimable.
- checkpoint JSONB exact `{codec:'source-checkpoint-v1',chunkIndex,highEventSeq,processedThrough,lastEvent,sealed}`; chunkIndex/highEventSeq UInt strings; lastEvent null or exact `{occurredAt,kind,entityKey,ordinal}`. checkpointHash hashes `{codec:'source-checkpoint-hash-v1',scope,revision,checkpoint}` with revision a JSON string, using the database JSONB recipe. Initial chunkIndex0/high=baseHigh/frontier=baseProcessedThrough/sealed=false, lastEvent copied from base checkpoint (or null). Job highEventSeq/eventCount/versionCount are separately constrained bigint columns; counts are THIS revision's counts, high=baseHigh+eventCount, versionCount=eventCount.
