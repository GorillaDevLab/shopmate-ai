# 前端功能缺口盘点

盘点基于当前分支代码和已合并的 D/F 系列实现，重点区分“后端已有能力”和“前端是否有可用入口”。

## 本次已补齐

- 登录页与表单：`/login`，调用 `POST /api/v1/auth/login`，由后端通过 HttpOnly Cookie 建立会话。
- 登录输入校验、提交中状态、服务错误提示。
- Dashboard 收到 401 时展示“重新登录”入口，不再只显示通用加载失败。

## 后端已有、前端仍缺入口

| 能力 | 当前证据 | 建议后续任务 |
| --- | --- | --- |
| 退出登录 | 当前认证模块只有 `POST /auth/login`，没有 logout 路由 | 增加清除 Cookie 的 logout API 与看板退出按钮 |
| 登录态路由保护 | 看板请求失败后才发现未登录，页面本身没有 middleware/登录态探测 | 增加未登录访问 `/` 的重定向策略，并保留 401 恢复兜底 |
| 商品列表/详情页面 | D4/D5 已提供 Schema 与 API，但 `apps/web/src/app` 没有商品路由 | 增加商品列表、筛选、详情页 |
| 商家切换/账号信息 | Merchant Scope 已在后端隔离，但前端没有商家信息或切换入口 | 后端提供可用商家列表后再做选择器 |

## 当前已有前端能力

- 经营看板、7/30 天与自选时段切换。
- Analytics API 趋势图、指标卡、库存提醒、热销商品。
- 暖白/石墨陶土与经典紫色主题切换。
- 加载、空数据、网络错误、会话失效状态。

这些缺口没有对应的现有 issue；建议按表格逐项新建任务，避免把“API 已完成”误认为“用户流程已完成”。
